## 三、几条贯穿全程的事实

**1. 真正动过原生层的只有 9 次。**
1.5、1.8、2.0.0、2.0.1、2.0.9、2.0.11-beta8、2.0.11-release、2.0.12-release、2.0.13-release。其余包 `classes.dex` 完全不变，`AndroidManifest.xml` 的差异只来自 versionCode / versionName。整个迭代主线是 Web 层。1.0.0-debug 的 dex 差异不计入——它和 1.0 是同一份代码的两种编译，差的是调试符号，不是功能改动。

**2. 更新链路连修四版才正常。**
2.0.2 / 2.0.3 误打包假 `version.json` → 永远「已是最新」；2.0.4 删掉后变 404；2.0.5 用绝对地址 + CORS 修好；2.0.7 又修了自动检测被 boot 状态清掉定时器。**因此 ≤2.0.4 的安装包必须手动装一次**，才能进入自动更新体系。

**3. 版本号有跳号与作废。**
缺 11（1.9.1，日志有记但产物未落盘）、19（2.0.7 中间构建）、43（发布几分钟即被 44 取代）；45（2.0.12）整体撤回。beta 系列占 23–33 共 11 个码位，正式版固定 34，是为了让装了 beta11 的设备满足 `latest > current`。

**4. 三条通道互相隔离。**
正式 `/update/version.json` + `/update/*.apk`、测试 `/test/*.apk`、网页端 `current/`。发测试包只动 `/test/`，不动清单，否则已装用户会被引导升级到未验证版本。网页端静态资源按「只加不删」同步，保留旧 hash 以兼容缓存。

**5. 文档本身有缺口。**
本仓库的 `dorm-app/dist-apk/VERSION_HISTORY.md` 覆盖到 2.0.14 正式版；2.0.15 beta1–3 的记录此前只存在于工作日志，本文件已补齐。
