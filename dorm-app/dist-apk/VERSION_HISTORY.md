## 二、八个阶段

1. **1.0–1.4（11-02 上午，5 版）**：从「能装能用」到「弱网不误报」。主线是连接可靠性，占了前 5 版全部精力。
2. **1.5–1.9（11-02 下午，5 版）**：视觉与启动体验。流体缓动、Splash、时间转盘、原生白屏/黑边修复。
3. **2.0.0–2.0.3（11-03 深夜，4 版）**：换后端到 `https://175.24.230.58`、服务器托管前端、App 内更新体系、机型与浏览器适配。
4. **2.0.4–2.0.9（11-04 凌晨→中午，6 版）**：文案收敛、更新链路连续 3 版修 bug、启动闪屏单套化、启动闪白。
5. **2.0.10 beta1–11 + release（11-04 下午，12 版）**：启动转场「Logo / 文字 / 底板接力」的 11 轮逐帧打磨，最后重新出正式包。
6. **2.0.11 beta1–8 + release（11-05 晚→11-06 凌晨，9 版）**：从「补设计稿」到「长内容」。先把 Ardot 里漏做的 Pin 水印与失败环补回来，再加公告体系（未读直开 → 常驻 → 正文全部搬到后端），把日志页改成固定头部 + 列表滚动，beta6–7 重做启动时序（整页先落位、Logo 后飞），beta8 上应用内下载安装。最后**发布 2.0.11 正式版**（code 44），Web 前端、更新包、`version.json` 一并推上线。
7. **2.0.12-release（11-06 00:52，1 版）**：2.0.11 上线后用户实测「下载完提示没有安装权限」——`REQUEST_INSTALL_PACKAGES` 只是声明，Android 8+ 还要用户在本机把「允许安装未知应用」打开。这一天没写新功能，只把这条系统权限的交互补全：自动跳开关页、回来接着装、允许后不重复下载。
8. **2.0.13-release（11-06 01:05，1 版）**：应用内下载走不通就干脆放下——2.0.11 上线后被「没有安装权限」卡住，2.0.12 补了引导但仍要用户去系统设置里点开关，体验划不来。这一版把更新面板退回最简形态：版本对比、更新条目、一句提示、两个按钮，点按交给系统浏览器下载。原生 `ApkInstallPlugin` 与 `src/apk.js` 都留着（不引用、不进包），`REQUEST_INSTALL_PACKAGES` 注释掉，随时能接回来。代码比 2.0.12 少了 1.8 KB（239,208 → 237,415）。

## 四、关键发现

### 1. 日志缺口：2.0.8
`.workbuddy/memory/2026-11-04.md` 从 2.0.7 直接跳到 2.0.9，没有 2.0.8 条目。拆包比对还原出它是「启动闪屏单套化」：把 `index.html` 里原本只有柠檬底 + 静态 Logo 的静态闪屏，升级为**自带完整入场动画的唯一一套闪屏**（内联 `<style>` 88 行：bsPop / bsRise / bsFade / bsSlide 四个 keyframes + `prefers-reduced-motion` 分支），同时删掉 React 组件与 `styles.css` 里那 23 个 `splash*` 规则块，避免「静态图标先画出来、React 再从 0 播一遍」。这是 2.0.10 那一整套 Logo 接力动画的地基。

### 2. 只有 8 次动过原生层

### 1) 日历铅笔糊（画布 `61:85`）

源图其实是 **1470×1470** 的调色板 PNG，之前只导了 64×64 当 2x/3x 屏用，等于把 4 倍的信息扔了。重新按 **256×231**（4x）导出 `pencil.webp`（19.3 KB，质量 95），并按设计稿的取景裁到内容边界；CSS 加 `object-fit: contain`，避免 256×231 被拉成 64×64。

### 2) 反馈详情标题和正文重复

后端只有 `content` 一个字段，前端把第一行当标题、又把整段当正文，单行反馈就会同一句话贴两遍（截图里 `12345678900000000hshhbsbs` 出现两次）。改为：多行才拆「首行标题 + 其余正文」；只有一段话时**不再造标题**，正文顶到标题位（`.fbd__ctext--lead`，3 行）。正文里的重复次数实测 1。

### 3) 提交的反馈截图太糊

选图后压到 720px 长边 / q0.72，1080×2400 的手机截图会变成 324×720。改为 **1600 长边 / q0.86**：同一张 1080×2400 压完 720×1600、单张 base64 ≈93 KB，3 张 1.2 MB，后端单次上限 4,000,000 字符、nginx 10m 都有余量。另加软预算 3.6M 字符，超了自动降一档（1200 / q0.78），避免长截屏被打回。

### 4) 反馈记录标题居中

`.fb__rec` 是 `<button>`，UA 默认 `text-align: center` 会被标题继承；`.fb__rtitle` 有 `width: 300` 所以文字被居中（编号行没定宽，缩到文字宽度反而看不出来）。修：`.fb__rec { text-align: left }`，并给标题/编号补 ellipsis 防止长标题溢出压到状态胶囊。

### 5) 反馈详情 3 张图只显示 2 张

`attach.slice(0, 2)` 的老实现只铺两张。改为最多 3 张（18/82/146），说明文字在 3 张时让到第三张右边（210）并简化成「点击看原图」，实测无重叠。

### 6) 新建任务的时间滚轮只能选 21:35~23:25

`.tw__col` 原来靠 `padding: 68px 0` 撑首尾留白 + `scroll-snap-type: y mandatory`；这种组合在部分 WebView 上会把可滚范围夹到两三格（表现就是只能停在某个区间）。改为：

- 首尾留白改成两个 `68px` 占位块（`padding: 0`），滚动范围回到完整 24 格 / 60 格；
- `scroll-snap-type: y proximity` + `overscroll-behavior: contain` + `touch-action: pan-y`，不再把滚动链递给底部面板；
- 松手后 `commit` 把 `scrollTop` 对齐到整格，避免停在两格之间导致「滚不动」的错觉；
- `.sheet` 也加 `overscroll-behavior: contain`。

实测 00:05 / 09:45 / 12:00 / 18:20 / 21:35 都能精确定位，连续滚动可一路滚到 00，两格之间松手自动对齐。

### 1) 漏签格没有叉号

画布 `26:60` 里漏签格的叉是独立矢量 `61:70「Vector 5」`（11.5×12.3、墨色描边、圆头），不在红格 frame 里，所以之前只落了红底。现在 `data-miss` 的格子补上叉，`data-ok` 仍是勾，两者不会串。

### 2) 登录页小狗没有入场

`[data-intro]` 那套首屏动画的**隐藏列表里有 `.login__dog`，但 `[data-intro="run"]` 的动画列表漏了它** —— 于是开场时它一直是 `opacity: 0`，等 `data-intro` 被删掉才「啪」地出现。现在给小狗单独一条 `introDrop`：从上方 18px 落下 + 轻微回弹（420ms `--ease-spring`），延迟跟着 `--i` 走（卡片 0 / 小狗 48ms / 底部 96ms）。实测中途能采到 0.56 → 0.96 的过渡帧。

### 4) 时间滚轮没有限制在 21:35–23:25

上一版把「只能选 21:35~23:25」当成故障去修（改成完整 0–23/0–59），方向反了。这版按业务窗口做**结构性约束**：

| 项 | 实现 |
| --- | --- |

| 小时列 | 只保留窗口覆盖到的小时 → 21 / 22 / 23 |
